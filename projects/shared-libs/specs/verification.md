# 验证方法与结论边界

验证应回答明确性质：逻辑是否成立、能否构建、如何呈现、真实硬件如何响应。
不同证据回答不同问题，某一层通过不能替代另一层结论。

## 可重复检查

从仓库根目录执行：

```sh
sh tools/check_host.sh
pio run -d projects/m5stack-stopwatch/bot-ux-watch
pio run -d projects/m5stack-core2/bot-ux-codex-core2
pio run -d projects/m5stack-core2/pps
```

主机脚本编译并执行当前纯 C++ 契约与真实 Bot renderer，产物写入 `tmp/host-checks/`。
共享实现变化时构建两个消费应用；PPS 私有实现变化时构建 PPS。
目录/文档变动检查相对链接、脚本路径及依赖发现，避免用无关重复构建替代路径检查。

| 对象 | 检查性质 | 无法据此证明 |
| --- | --- | --- |
| Watch 输入/RTC/电源测试 | 边沿、超时、恢复、错误处理、NVS 兼容与回绕 | 触摸 IC、PMIC 实体键、实际电流 |
| 字体/图形/蒙版测试 | 字形覆盖、RGB565 混色、几何边界、解码可重复性 | 面板亮度、反射、视觉舒适度 |
| Bot renderer | 1,120 组合、多尺寸包含、过渡、镜像、低/零运动、周期 | 设备 FPS 与显示传输成本 |
| HID/信号/灯帧测试 | 报文、状态投影、通知和 RGB 生成 | 宿主接收、蓝牙连接或真实灯光 |
| 声音/发送器测试 | 波形、借用缓冲、排队、阻塞隔离、暂停/恢复 | 声压、失真及驱动永不阻塞 |
| PlatformIO 构建 | 与固定 SDK、板卡和链接配置兼容 | 已烧录、已连接或已完成实机验收 |

## 原生图例与诊断

[Bot 预览工具](../bot-ux/tools/host-preview/README.md) 编译真实 `BotUx.cpp`，
生成 RGB565/SVG 和图鉴帧。PNG/GIF 是源码示例，动画循环来自有限采样，不能当作设备录像。
[帧抓取工具](../../../tools/capture_device_frame.py) 读取固件画布，也不是面板摄影。

Watch `contact` 与 `td/tm/tu` 分别测试原始接触后的应用路径与 UI 指针路径；
它们都绕过物理触摸 IC。Core2 诊断应区分仅设置页点击与真实发送 HID 的命令。
`PERF` 用于运行时帧时、堆/PSRAM、连接及发送错误；串口传输帧率不是稳定动画 FPS。

## 保留结论的标准

物理结论必须带配置与范围，例如主机版本、底座、供电、亮度和负载。
确定测得的结果写为该配置下的事实；尚未测量的项目保持未知，不用计划或实现推断代替。
规格保留能影响设计的结论与限制，逐次命令、设备端口、临时产物哈希和过程记录不构成契约。
