# 共享组件与宿主职责

共享层提供角色、原生 UI、输入模型和声音。StopWatch 与 Core2 各自拥有业务状态与硬件，
PPS 独立使用其私有驱动。共享意味着可复用的接口和行为，不意味着所有设备已兼容同一 SDK。

## 所有权决定边界

| 层 | 拥有 | 不应承担 |
| --- | --- | --- |
| BotUx | 表情、角色运动、临时反应、视线、名称与说明 | 显示器提交、主机任务事实、设备电源 |
| UX components | RGB565 渲染、字体、指针/滚动、键盘、声音源和输出适配 | 页面导航、NVS、设备输入策略 |
| StopWatch | RTC、触摸/按键、表盘/设置、环境轮播、电源和音频生命周期 | 用本地情绪暗示外部任务进度 |
| Core2 Codex | BLE/RPC、槽位灯光投影、命令、卡片/侧灯/声音 | 把未知颜色或绿色解释成可靠任务完成 |

组件不直接驱动显示器，使同一实现可渲染到表盘、工具栏和设置预览。
宿主为预览使用独立实例，使试选不会覆盖持久配置或正在接收的主机状态。
时间、输入、网络和电源状态由实际拥有者提供，组件不制造联网、电量或任务信息。

## 集成决策

现有设备工程使用 PlatformIO/Arduino，各自固定依赖版本。位于
`projects/<brand-model>/<project>/` 的工程通过 `../../shared-libs` 查找库。
BotUx 仍依赖 M5Canvas；新厂商的移植需要实现和验证绘制适配，不能仅因目录通用化就声明支持。

字体按字号/字集拆为独立编译单元，PCM 与合成声按需链接，使小工程不承担未使用功能。
UI 字色与 Bot 眼色独立，RGB565 所有权、覆盖率混色和缓冲生命周期保持明确。
热路径采用有界状态与固定缓冲，避免每帧分配造成响应不稳定。

图鉴由真实 BotUx 源码的主机 renderer 生成；浏览器只播放已生成帧。
这样语义、图例和测试使用同一实现，但主机图元近似与 GIF 采样仍不等同于设备显示。

## 规格维护方式

规格描述当前事实、设计决策、观点及因果，未知条件明确写出。实现变动时重写对应主题，
不在文尾追加任务时间线、代理分工、命令输出、提交哈希或烧录流水。
同一规则在所属组件或工程中定义，其他文档链接引用。代码历史由 Git 保留，
临时调查与运行日志放在忽略的 `tmp/`；有长期价值的结论转化为有条件的事实与验证边界。
