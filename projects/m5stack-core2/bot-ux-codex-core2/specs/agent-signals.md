# 主机信号投影与通知

`AgentSignal` 将已就绪的槽位灯光投影为 UI 状态。它知道颜色和效果，不知道任务身份、
标题、结束原因或审批详情，因此这些状态仅用于显示与有限提醒。

## 精确解码

仅效果 1（solid）或 4（breath）使用下表；未知效果/颜色为 Unknown。
未就绪为 Unknown，效果 0 或已支持效果下的黑色为 Off。

| RGB24 | 状态 | 展示含义 |
| --- | --- | --- |
| `0xFFFFFF` | Idle | 空闲 |
| `0x304FFE` | Working | 工作中 |
| `0xFF6D00` | NeedsInput | 需要输入；不能区分审批与回复 |
| `0x00FF4C` | NewReply | 新回复；不是任务完成 |
| `0xFF0033` | Error | 错误信号 |

亮度是灯光偏好，不是生命周期：亮度零可保持已知信号，但输出灯必须黑。
不按“相近颜色”猜测状态，避免主题色或未知宿主效果被误解成任务事件。

## 为什么不能从颜色推导任务事实

同一槽位可以换任务，宿主也可能用槽位表达引导、导航或其他 UI 状态。
全灭可以来自主机灯光策略，不证明断连或完成；常规状态轮询不能代替用户活动。
固件不伪造 HID 活动阻止主机调暗，也不绕过宿主的灯光偏好。
可靠任务身份、区分输入原因和完成事件需要独立语义协议，当前没有这些字段。

## 状态模型

每槽保存 `zone/signal/revision/changedAtMs`。信号或灯光字段变化才增修订号；
重复包不重启动画，全局 revision 每次有变化的 update 增一次。这些是本地显示版本。

连接变化清空缓存。第一份应用就绪且新鲜的槽位快照建立静默基线；全灭暂停基线，
重新亮起静默恢复。Unknown/Off→已知状态也不提醒。
原因是这些变化可能仅表示恢复观察能力，不能视为刚发生的任务事件。

已知活动状态进入 NeedsInput/Error 或 Working→NewReply，可设置一次对应槽位通知位。
每槽冷却默认 2,500 ms，被冷却抑制的事件丢弃，不延迟补播，时间比较支持回绕。
多槽通知可以合并为一声，并同时高亮卡片，但不自动切换用户选择的 Bot。

## 展示与因果

卡片背景使用本地固定槽位身份色，独立状态点保留主机原始 RGB，文字使用精确状态名。
因此六个 Working 仍能区分槽位，同时不篡改蓝色状态含义。
选中 Bot 依据所选槽投影：Working→Working，NeedsInput→Waiting，Error→Blocked，
Idle→Idle；新回复可以有短暂开心回应，但不能改名为 Done。

Working→NewReply 的去重事件可触发最长 30 秒的吸引注意效果，交互、状态变化或失去就绪
提前清除；持续绿色不会续期，重连基线不会启动。实现见 [反馈](feedback.md)。

## 实现与检查

[AgentSignal.h](../include/AgentSignal.h) 和 [FreshReplyAttention.h](../include/FreshReplyAttention.h)
定义解码与窗口。`agent_signal_test`、`fresh_reply_attention_test` 检查未知值、就绪、
亮度、重复包、基线、冷却、窗口与回绕；这些测试不证明主机颜色的任务语义超出上述字段。
